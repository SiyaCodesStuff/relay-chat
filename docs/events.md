# Socket event contract

## Reconnect and reliable sends

`channel:sync` accepts `{ channelId, after: messageId | null, lastSeen?: messageId | null }` and requires current membership. On reconnect, the client sends its latest observed ID as `lastSeen` and its confirmed history checkpoint as `after`. The server queries from `after` to include any unseen messages below an out-of-order live ID. It acknowledges `{ ok: true, messages, hasMore }` or `{ ok: false, error }`. Each page contains up to 100 non-deleted stored messages, strictly ascending by ID and strictly after the supplied cursor. Continue from the last returned ID while `hasMore` is true; `null` starts at the beginning. Live room delivery is enabled before querying history, so history/live overlap is expected. Messages and send acknowledgements include `clientMessageId`.

Use `createReliableChatClient` from `@relay-chat/shared` with an injected Socket.IO-compatible socket, per-channel history checkpoints, and callbacks `onMessage`, `onSendState`, and `onSyncError`. `onSynced` optionally signals catch-up completion. The module is independent of React. It buffers live events during sync, processes ascending history pages, and deduplicates by stored ID and `(userId, clientMessageId)`. Only ordered catch-up pages advance checkpoints; live events may arrive out of order across instances, so reconnect deliberately replays overlap rather than skipping an unseen message. Socket message ID allocation is serialized through a PostgreSQL transaction advisory lock, ensuring new IDs advance in commit order even across instances or clock changes.

Call `send({ channelId, body, clientMessageId })` with one generated ID per logical send. Offline sends remain queued; connection loss requeues in-flight sends. All transport retries reuse that ID. Acknowledgements time out after 5 seconds; sends try at most three times before becoming `failed`. `onSendState` exposes queued/sending/sent/failed states and error codes, including `ACK_TIMEOUT`. Server rejections fail immediately. `retry(clientMessageId)` explicitly retries a failed send with its original ID. The default pending-send limit is 100; a full queue throws `SEND_QUEUE_FULL` rather than dropping a message. A sync timeout/error calls `onSyncError` and leaves queued sends intact; call `reconnect()` to retry synchronization.

`getMessages()` returns the deduplicated collection in ascending ID order for rendering, `getSends()` exposes queue state, and `getCursors()` exposes safe history checkpoints. Call `dispose()` when leaving a chat session. This queue survives network disconnects for the lifetime of the module; it is in memory and does not survive a page reload. Persisting browser drafts or queues across reloads is outside this contract. Catch-up recovers messages, not edit/deletion events.

Connect to the Socket.IO server with the `relay_session` cookie and an `Origin` value listed in `ALLOWED_ORIGINS`. Connections without either are rejected. The server joins the socket to each channel the authenticated user currently belongs to.

## Multiple API instances

The server accepts WebSocket transport only. Clients must connect using `io(url, { transports: ["websocket"] })`. HTTP long-polling is disabled: polling sends multiple HTTP requests for one Engine.IO session, which would require sticky routing to the instance owning that session. A WebSocket uses one connection, so no sticky sessions are needed. Configure the reverse proxy to forward WebSocket upgrades.

Every instance attaches the Socket.IO Redis adapter with dedicated publisher and subscriber connections before listening. Redis Pub/Sub forwards channel events and room operations between instances. All instances must use the same Redis, PostgreSQL, adapter channel prefix, and origin/session configuration. PostgreSQL owns messages, idempotency, membership and ban state; Redis owns sessions, rate counters and presence leases. No instance-local cache is authoritative for those decisions. Redis Pub/Sub is live delivery, not a durable queue: disconnected clients recover history through the REST cursor API.

Only live connection objects and transient typing timers remain local to their owning WebSocket. Typing is deliberately never persisted; clients expire indicators locally after a server loss. Presence survives instance loss through Redis lease expiry and reconciliation by surviving instances.

All payloads are defined in `@relay-chat/shared` and are validated on receipt. The server limits each socket to 30 events per 10 seconds and rejects Socket.IO payloads over 16 KiB.

| Direction       | Event             | Payload                                                | Result                                                                                                                                                                                                                                                        |
| --------------- | ----------------- | ------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Client → server | `channel:join`    | `{ channelId }`                                        | Joins the channel room only when the caller is currently a member. Its acknowledgement is `{ ok: true }` or `{ ok: false, error }`. This follows a successful REST join.                                                                                      |
| Client → server | `message:send`    | `{ channelId, body, clientMessageId }`                 | The server checks current membership, stores the message before emitting it, and acknowledges with the stored message or a typed error. Reusing a `clientMessageId` for the same user returns the original stored message and does not broadcast a duplicate. |
| Client → server | `typing:start`    | `{ channelId }`                                        | Relayed to other currently authorised channel sockets.                                                                                                                                                                                                        |
| Client → server | `typing:stop`     | `{ channelId }`                                        | Relayed to other currently authorised channel sockets.                                                                                                                                                                                                        |
| Server → client | `message:new`     | `{ id, channelId, userId, body, createdAt, editedAt }` | A persisted new message. Timestamps are ISO-8601 strings.                                                                                                                                                                                                     |
| Server → client | `typing:start`    | `{ channelId, userId }`                                | Another authorised member began typing.                                                                                                                                                                                                                       |
| Server → client | `typing:stop`     | `{ channelId, userId }`                                | Another authorised member stopped typing.                                                                                                                                                                                                                     |
| Server → client | `presence:update` | `{ userId, status }`                                   | `status` is `online` or `offline` for a member sharing a channel room.                                                                                                                                                                                        |
| Server → client | `error`           | `{ code }`                                             | Typed protocol error: `INVALID_PAYLOAD`, `NOT_AUTHENTICATED`, `NOT_A_MEMBER`, `RATE_LIMITED`, or `INTERNAL_ERROR`.                                                                                                                                            |

Before handling every client event, the server checks the user’s current ban state and channel membership in PostgreSQL. Before broadcasting a channel event, it removes sockets whose owners no longer have membership, so a removed member cannot receive a later channel event.

Presence counts Redis connection leases per user across tabs and instances. Leases last 30 seconds and are renewed every 10 seconds. Only the first connection emits `online`; closing the final connection emits `offline`. Surviving instances sweep expired leases every 10 seconds and broadcast offline changes after a crash. With no running instance, expiry is reconciled when an instance starts again. Redis server time determines lease deadlines.

Typing updates sent by the server contain `{ channelId, userId }`. Starts are throttled to once per second per socket/channel. Each accepted start refreshes a three-second in-memory expiry, which emits `typing:stop`; explicit stops and disconnects also clear typing. Typing is never written to Redis or PostgreSQL. Clients should also expire indicators locally so an instance crash cannot leave a stale indicator.
